## Remaining unverified risk (blocking physical GO)

- **P1 UI safe area:** Android status bar overlaps Driver Mode header in screenshots. Must use real safe-area insets and run Android screenshot checks, font scaling, and orientation. This work is not addressed by this isolated smoke patch.
- **BLE:** test device power cut during probe, handshake, Check, and Live, followed by recovery and BLE owner/lease validation. Mocked Jest cannot prove Android radio lifecycle.
- **Live:** test repeated ECU timeouts after recovery, stop during retry delay and during native BLE connect, duplicate foreground-service callbacks, race with app unmount, persistence errors and stopped session uniqueness.
- **Check:** test 0100 empty bitmap/0101 monitor bits against actual KWP raw protocol handling; do not infer unsupported capability without consistent evidence. Reopen sealed Check after process restart and reverify hash.
- **TTS:** Android `TextToSpeech.speak` returns enqueue acceptance, **not utterance completion**. Native module has no `UtteranceProgressListener`; speech may be preempted or unavailable despite a fulfilled JS promise. Implement utterance completion callbacks, locale availability checks and severity-aware preemption before certifying safety voice.
- **Security:** internal policy NO_CRITICAL is not the same as zero-high public security certification.

## i18n / TTS architecture

The app already stores `voiceLanguage: 'en-US'|'es-ES'` in AsyncStorage and couples app UI language to voice. `uiText(en, es)` is present but not systematic, leaving hardcoded and mixed strings.

Progressive migration target: typed keys backed by JSON dictionaries `messages.en.json`/`messages.es.json` and `uiMessage(key, language)`. A locale is **user state**, never an environment/build variable. Use a default locale and a controlled fallback with a parity gate, then move one screen at a time to keyed copy. This patch starts with motion state only; it does NOT claim the rest of the UI is localized.

Speech is independent of displaying translations: app raises `DriverAlertKey`, resolves a safe short phrase using `DriverAlertLexicon`, sends phrase **plus a BCP-47 language tag** to native Kotlin's `TextToSpeech.setLanguage`, and Android chooses an installed synthesizer voice (no online LLM or translation needed). If `LANG_MISSING_DATA` or `LANG_NOT_SUPPORTED`, report unavailable, never claim audio success. Consider separate UI and voice-language settings so Spanish UI with English spoken warnings remains possible. Preserve English default in migration.

## Hardening pass 2 — voice completion and severity (2026-10-16)

- Android Kotlin TTS now exposes `speakAlert(text, languageTag, priority)`; the JS driver layer refuses the older enqueue-only `speakLocalized` bridge.
- The Promise resolves `true` only when `UtteranceProgressListener.onDone` is delivered for the current utterance. `onError`, `onStop`, missing locale, initialization failure, preemption and a 15-second watchdog resolve `false`.
- Lower priority voice cannot preempt an active critical utterance; overlapping utterance IDs are matched to avoid late old callbacks resolving a newer request.
- This is source-level implementation plus structural CI, **not proof of Kotlin compilation, hardware audio, installed voice data, volume, audio route or operating-system process survival**. Actual native compilation and Android instrumentation remain open until a gated APK is authorized.

## Hardening pass 3 — durable language preference

- The Settings UI now serializes preference writes, disables concurrent toggle/button updates during persistence, and switches shared UI/voice locale only **after** storage confirms the write.
- If storage fails, settings roll back to the previous locale and display a localizable error; no unhandled Promise rejection from the Settings controls.
- `SettingsScreen.persistence.test.tsx` injects a pending write and a rejected write, asserting no premature language switch and an explicit visible error.

## Hardening pass 4 — one-shot interruption alerts

- Live interruption no longer creates arbitrary English spoken prose. The session interruption sends the semantic `SESSION_INTERRUPTED` key through the preference-aware `DriverVoiceNotificationService`, which chooses locale, phrase and native severity priority. Detailed reasons remain in stored/visual evidence instead of a long robotic sentence.
- A new CI test forces English, Spanish and muted preferences and verifies the native voice boundary arguments.

## Hardening pass 5 — live voice locale consistency

- DriverPreferences now broadcasts changes only after AsyncStorage confirms successful persistence.
- Live subscribes to durable changes and ignores older in-flight preference reads; unmount cleans its listener.
- A language switch resets Live voice cooldown memory so a still-active safety alert can be announced in the newly selected locale, subject to alert-level preferences.
- New fault-injection CI checks pending writes, write failures and unsubscribe cleanup. No database/cloud localization dependency.

## Additional recovery audit: confirmed self-deadlock and native initialization timeout

- **Fixed pending regression:** Exhausted `attemptConnectionRecovery()` awaited terminalization, while `performStop()` awaited the exact same `recoveryPromise`. This promise cycle could freeze the session permanently. Terminalization is now dispatched without awaiting from within the recovery task.
- **Fixed bounded stop:** waiting for a native GATT discovery/reconnect promise now has a 9 s stop settlement ceiling and fail-closed interruption path. Late reconnect outcomes retain a terminal guard; native instrumentation remains required.
- **Fixed TTS initialization hang:** if Android never calls `TextToSpeech.onInit`, a bounded 8 s watchdog resolves pending requests false, and tears down the unusable native engine.
- **Fixed durable preference listeners:** one subscriber throwing cannot misreport a successful AsyncStorage write as failure.
- New Jest fault-injection tests cover recovery exhaustion, perpetual discovery, observer exceptions and Kotlin watchdog structure. Native compilation remains a separate gate.
